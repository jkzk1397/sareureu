# 화면 쉽게 만들기 (2026-11-15 정리)

> **커서에서 쓰는 법**: `@docs/UI_SIMPLIFY_TODO.md 작업 2 진행해줘`처럼 한 번에 하나씩 맡긴다. 작업 하나 = 브랜치 하나 = PR 하나.
> 끝난 작업은 제목 앞에 ✅를 붙인다. **전부 끝나면 이 파일을 지운다.**
> 권하는 순서: 2 → 3 → 4 → 5 → 6 → 7. 작업 8은 화면이 아니라 AI 쪽이라 따로.

## 왜 하는가
실제로 폰에 깔아 써 보니 앱이 어렵고 글자가 많았다. 눌러도 반응 없는 칩, `o1~o12` 번호 목록, 이해하기 어려운 경로 띠 그림, 설정의 긴 설명이 문제였다. 과제용이 아니라 처음 깐 사람이 설명 없이 쓸 수 있어야 한다.

## 바꾸지 않는 틀
- 숫자는 코드가 세고 AI는 문장만 쓴다. AI 문장은 검증 통과본만 보인다
- 막는 앱이 아니라 말 거는 친구다. 다른 앱을 닫거나 누르지 않는다
- 관찰(코드)과 추측(AI)은 화면에서 구분한다. 구분하는 방법만 쉽게 바꾼다
- AI 문장마다 신고할 수 있어야 한다(Play 정책). 개인정보와 국외 이전 고지는 지우지 않는다. 접을 수는 있다
- 시연 모드에서 모든 화면이 돌아가야 한다
- 르르 반말 말투, 디자인 토큰, `BuddyAvatar` 하나로 그리기

## 모든 화면에 적용할 기준
1. **결론부터.** 화면을 열면 첫 화면 안에 "그래서 어떻다는 건지"가 한 문장으로 보인다
2. **한 화면에 주 버튼 하나.** 나머지는 글자 버튼
3. **자세한 것은 접는다.** 처음에는 접혀 있고 누르면 펼쳐진다
4. **누를 수 있게 생긴 것은 누르면 반드시 눈에 보이는 반응이 있다.** 반응이 없으면 누를 수 없게 그린다
5. **안에서 쓰는 말을 화면에 쓰지 않는다.** 아래 표대로 바꾼다
6. **설명 문장은 한 줄.** 두 줄이 넘으면 '자세히'로 접는다

| 쓰지 않는 말 | 화면에 쓰는 말 |
|---|---|
| 세션 | 번 (한 번 볼 때) |
| 중앙값 | 보통 |
| 기준선, 기준선 대비 | 시작할 때, 시작할 때보다 |
| 맥락 | 때 (어떤 때) |
| 기록률 | 기록된 비율 |
| 관찰 3, o3 | 그 기록의 문장 자체 |
| 확신 높음/중간/낮음 | 꽤 그런 것 같아 / 그럴 수도 있어 / 잘 모르겠어 |
| 모의 AI, 규칙 기반 | 기본 문장 (AI 없이) |
| 검증 통과 | AI 답 사용 |
| 모의 결과로 대신 | 기본 문장으로 대신 |
| 지문(해시), ms | 화면에서 숨김 ('자세히' 안) |
| 코드가 계산한 요약 | 앱이 센 요약 숫자 |
| 원시 사용 기록 | 앱을 열고 닫은 기록 |
| 임계값 | 알림 기준 |
| N단계 | 표시하지 않음 |

용어집(AGENTS.md 9절)의 **코드 이름은 그대로** 둔다. 바꾸는 것은 `strings.xml`의 화면 말뿐이다.

## ✅ 작업 1. 리포트 탭 (PR #21)
결론부터 보이게 순서를 바꾸고, 근거는 눌러서 문장으로 펼치고, 경로 띠 그림을 순위 막대로 바꿨다.
**폰에서 확인할 것**(빌드 검사만 통과했고 실제 화면은 아직 못 봤다): 가설 카드의 '왜 이렇게 생각했어?', 맨 아래 '기록 더 자세히 보기', 큰 글자 설정, 다크 모드. 어색하면 이 작업 안에서 고친다.
리포트에서 더 이상 쓰지 않는 `core:designsystem`의 `FlowDiagram`, `HypothesisCard`, `EvidenceChip`은 다른 곳에서도 안 쓰면 지운다(목업 문서 `docs/06_DESIGN_SYSTEM.md` 6절과 9절도 같이 고친다).

## ✅ 작업 2. 설정 탭: 13개 구역을 접는 묶음 6개로
지금은 감지, 하루 리듬, 예약 알림, 알림 기준, 추적 앱, AI 사용 방식, AI가 한 일, 개인정보, 화면, 시연, 개발자 메뉴, 정보가 한 줄로 길게 이어진다.

- 파일: `feature/settings/`의 `SettingsScreen.kt`, `SettingsSections.kt`, `SettingsAi.kt`, `SettingsMonitoring.kt`, `SettingsPrivacy.kt`, `strings.xml`
- 묶음(제목 줄을 누르면 펼쳐진다. 처음에는 모두 접힘. 제목 줄 오른쪽에 지금 값을 한 마디로 보여 준다)
  1. **알림**: 알림 기준(평소, 밤), 예약 알림, 하루 리듬 고치기 · 요약 예: "평소 10분, 밤 5분"
  2. **감지**: 감지 켜기, 추적 앱, 감지 방식, 배터리 안내 · 요약 예: "켜짐"
  3. **AI**: AI 사용 방식, AI가 한 일 · 요약 예: "클라우드 AI"
  4. **개인정보**: 세 줄 요약, 내보내기, 모두 삭제
  5. **화면**: 테마, 녹는 각설탕 보기
  6. **더 보기**: 시연 모드, 개발자 메뉴, 정보
- 감지가 꺼져 있으면 묶음 밖 맨 위에 '감지 켜기' 카드 하나를 따로 둔다(가장 중요한 상태라 접지 않는다)
- 긴 설명(`settings_monitoring_desc`, `settings_ai_cloud_send`, `settings_privacy_*_body`, `settings_export_desc` 등)은 한 줄 요약 + '자세히'로 접는다. 고지 문장 자체는 지우지 않는다
- **AI가 한 일**: 한 줄에 "11/15 16:29 주간 분석 · AI 답 사용"처럼 날짜, 기능, 결과만. 줄을 누르면 이유, 걸린 시간, 지문과 길이, 받은 답이 펼쳐진다. 제공자 이름(클라우드, 기기 안, 기본 문장)은 펼친 안에 둔다. 최근 5개만 보이고 '더 보기'
- 새 내비 경로는 만들지 않는다(화면 안 접기만 쓴다). 펼침 상태는 `rememberSaveable`
- 끝난 기준: 설정을 열면 스크롤 없이 묶음 6개가 다 보인다. 시연 모드 켜기까지 누르는 횟수가 2번 이하

## ✅ 작업 3. 화면 위 카드와 버블 (`core:intervention`)
숏폼 위에 뜨는 카드가 이 앱의 핵심이라 가장 쉽게 읽혀야 한다.

- 파일: `overlay/NudgeCards.kt`, `overlay/BuddyBubble.kt`, `strings.xml`
- 'N단계' 배지(`intervention_level_badge`)를 화면에서 뺀다. 단계는 사용자에게 뜻이 없다
- 버튼 순서와 무게를 모든 단계에서 같게: '그만 볼래'가 주 버튼, 'N분만 더'가 보조, '오늘은 그만 알려 줘'는 글자 버튼
- 3단계 입력 문장(`intervention_type_to_extend_l3`)이 길어 폰 키보드로 치기 어렵다. 뜻은 두고 20자 안으로 줄인다
- 카드 한 장에 문장 2줄, 버튼 3개를 넘지 않게 한다. 넘는 단계는 줄인다
- 버블을 눌렀을 때 나오는 패널: "N분째", "N분 뒤에 말 걸게", 버튼 두 개만
- 개입 규칙(언제 뜨는지, 단계가 오르는 조건)은 바꾸지 않는다
- 끝난 기준: 시연 모드 '숏폼 보기 시작'으로 1~4단계 카드를 모두 띄워 스크린샷을 PR에 붙인다

## ✅ 작업 6. 친구 탭
서버가 없어 지금은 전부 가상 친구다. "곧 열려요"가 여러 곳에 흩어져 있어 고장 난 것처럼 보인다.

- 파일: `feature/friends/`의 `FriendsScreen.kt`, `FriendsPokeCard.kt`, `FriendsChallenge.kt`, `strings.xml`
- 맨 위에 안내 한 줄만: "지금은 가상 친구로 미리 보기야. 진짜 친구 연결은 준비 중"
- '+ 초대' 버튼과 '주간 리그 · 곧 열려요' 카드는 서버가 열릴 때까지 화면에서 뺀다(코드는 `// TODO(#이슈번호)`로 남긴다)
- 랭킹 부제 "내 기준선 대비 · 기록률 80% 넘는 날만 계산" → "시작할 때보다 얼마나 줄었는지". 계산 조건은 '자세히' 안
- 잔소리 맡기기: 친구 고르기 → 한 줄 쓰기 → 맡기기 세 걸음이 한 화면에서 위에서 아래로 보이게. 규칙 안내는 한 줄만
- 차단과 신고는 친구 이름 옆 메뉴 안으로

## ✅ 작업 8. AI 쪽 남은 문제 (화면 아님)
1. **문구 팩 클라우드 호출 실패**: 설정 › AI가 한 일에 "ServerException; 스키마: JSON을 읽을 수 없음"(17초)으로 남고 기본 문장으로 대신된다. 출력이 길어 중간에 잘리는 것으로 보인다. `core:ai`의 문구 팩 생성기에서 최대 출력 토큰과 응답 형식(JSON 모드)을 확인하고, 필요하면 맥락별로 나눠 부른다. 무료 한도를 넘지 않게 하루 호출 수는 늘리지 않는다
2. **검증기 빈틈**: 한 주 합계 `{topContextMin}`을 "누를 때마다", "볼 때마다"처럼 매번의 양으로 쓴 문장이 통과한다. `ReportRules.timeMeaning()`의 금지 말에 '때마다'를 더하고 `GeminiTimeMeaningTest`에 사례를 추가한다. 프롬프트는 새 버전 파일로만 고친다
3. **알림 기준을 보는 중에 바꾸면** 다음 번 볼 때부터 적용된다. 설정의 알림 기준 아래에 그 사실을 한 줄로 알린다

## 모든 작업의 확인 방법
1. `./gradlew spotlessApply` → `./gradlew check`
2. `./gradlew installDebug`로 폰에 깔고 설정 › 더 보기 › 시연 모드 › 2주치 가상 기록 넣기
3. 바꾼 화면을 라이트, 다크, 글자 크기 최대에서 각각 본다
4. 바꾸기 전후 스크린샷을 PR에 붙인다
5. 누를 수 있는 것을 전부 한 번씩 눌러 본다
