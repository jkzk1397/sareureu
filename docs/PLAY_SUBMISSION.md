# Play Console 제출 문안 (초안)

> 담당: R1 · 사람이 Play Console에 옮겨 적고 동영상을 찍어 제출한다. 정책 근거는 `docs/research/policy.md`(1·2·3·6·8절).
> 여기 적힌 문구는 앱 안 문구·매니페스트와 **글자 그대로 같아야** 한다. 앱 문구를 바꾸면 이 문서도 같이 고친다.

## 1. 포그라운드 서비스 선언 (Policy › App content › Foreground service permissions)
| 항목 | 내용 |
|---|---|
| 서비스 | `core/intervention` `MonitorService` |
| 유형 | `specialUse` 하나 (`FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`) |
| 매니페스트 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` | 사용자가 켠 동안 숏폼 앱 사용 시간을 세고 기준 시간에 화면 위 알림을 띄움 |
| 기능 설명 | 사용자가 설정 › 감지 켜기를 누른 동안, 숏폼 앱(유튜브·인스타그램·틱톡)이 화면 맨 앞에 있는 시간을 사용 기록 API로 세고, 사용자가 정한 기준 시간이 되면 화면 위 캐릭터와 카드로 알린다. 다른 앱을 닫거나 조작하지 않는다. |
| 중단·지연 시 영향 | 숏폼을 보는 동안 카드·메시지 알림이 뜨지 않고, 그 시간이 기록되지 않아 리포트의 하루 합계가 실제보다 적게 나온다. |
| 사용자 인지 | 사용자가 직접 켠다. 켜져 있는 동안 상태 알림(채널 `service_status`)이 보이고, 설정에서 언제든 끌 수 있다. |
| 시작 조건 | 앱이 화면에 있을 때 사용자의 탭으로만 시작. 재부팅 뒤에는 사용자가 켜 둔 경우만 다시 시작(`specialUse`는 부팅 시작 금지 목록에 없음). |
| 동영상(찍을 장면) | ① 앱 실행 → 설정 › 감지 켜기 → 사용 기록 고지 화면 → 시스템 설정에서 허용 → 돌아와 감지 켜짐, 상태 알림 확인 ② 유튜브 쇼츠를 기준 시간(테스트용으로 5분 설정)까지 시청 → 화면 가장자리 캐릭터 → 카드 1단계 ③ '그만 볼래' → 홈 화면 ④ 설정 › 감지 끄기 → 상태 알림이 사라짐 |
| WorkManager로 안 되는 이유 | 숏폼을 보는 동안 몇 초 단위로 앞 화면 앱을 확인해야 하고(기준 시간 ±30초), WorkManager 최소 주기(15분)로는 불가능하다. 화면이 꺼지면 확인을 멈춘다. |

## 2. 사용 기록 접근 (PACKAGE_USAGE_STATS)
- 전용 선언서는 없지만 User Data 정책상 민감 정보 → **앱 안 눈에 띄는 고지**(온보딩·설정의 "사용 기록 접근을 켤까?" 화면, 다른 고지와 묶지 않음, 뒤로 가기는 동의 아님) + 개인정보처리방침 + Data safety.
- 고지 화면 문구 원본: `feature/onboarding/src/main/res/values/strings.xml`(사용 기록 고지 키).
- `QUERY_ALL_PACKAGES`는 쓰지 않는다. `<queries>`에는 추적 앱 7개 `<package>`와 MAIN/LAUNCHER `<intent>`만.

## 3. 접근성 서비스
- **선언하지 않는다.** 정밀 모드(`AccessibilitySource`)는 P1로 만들지 않았다. 나중에 넣으면 Play Console 접근성 선언과 동영상(거절 흐름 포함), 별도 고지 화면(`docs/research/policy.md` 3절 문안)이 필요하다. `isAccessibilityTool`은 선언하지 않는다.

## 4. Data safety (초안 — 항목 이름은 Play Console 화면에서 다시 확인)
| 데이터 | 수집 | 공유 | 기기 밖 전송 | 목적 | 선택 여부 |
|---|---|---|---|---|---|
| 앱 사용 기록(어떤 앱이 언제 앞에 있었나 — 추적 앱과 직전·직후 앱의 **종류**) | 예(기기 안 저장) | 아니요 | 아니요(원시 기록은 기기 밖으로 나가지 않음) | 앱 기능(숏폼 시간·경로 분석), 개인화 | 필수 아님(거절 시 시연 모드) |
| 앱 안 활동(카드 응답, 계획, 판정, 채팅) | 예(기기 안) | 아니요 | AI를 '클라우드'로 켠 경우 채팅 문장(전화번호·이메일 가림)과 계산된 주간 요약만 Google에 처리 위탁 | 앱 기능 | 선택 |
| 프로필(닉네임·연령대·신분·하루 리듬·관심사) | 예(기기 안) | 아니요 | 클라우드 AI를 켜면 연령대·신분·관심사·목표·말투만(닉네임 제외) | 개인화 | 연령 확인 외 선택 |
| 위치·연락처·사진·설치 앱 전체 목록 | 아니요 | — | — | — | — |
- 전송 중 암호화: 예(HTTPS, Firebase).
- 삭제 요청: 앱 안 설정 › 개인정보 › 모든 기록 삭제(로컬 전부). 원격 데이터는 친구 기능(P1)을 켜기 전에는 없다.
- 데이터 처리 위탁: Google LLC(Firebase AI Logic, Gemini Developer API) — 사용자가 'AI 사용 방식'에서 클라우드를 고르고 동의한 경우만.

## 5. 개인정보처리방침에 넣을 항목 (요약)
1. 수집 항목과 목적: 위 4절 표.
2. 보관 기간: 원시 사용 기록 7일, 숏폼 세션·개입 기록·메시지·계획·가설 90일, AI 감사 로그 30일, 프로필은 삭제할 때까지 — 모두 기기 안.
3. **국외 이전(개인정보 보호법 제28조의8)**: 이전받는 자 Google LLC / 국가 미국 / 항목: 코드가 계산한 주간 요약(맥락별 분·감소율·위험 시간대·앱 종류), 연령대·신분·관심사·목표·말투, 코치 채팅 문장(전화번호·이메일 가림) / 목적: AI 응답 생성 / 시기·방법: 사용자가 앱을 쓰는 중 요청 시 HTTPS 전송 / 보유: Google 약관에 따름 / 거부 방법: 설정 › AI 사용 방식 › 쓰지 않기(규칙 기반 문장으로 동작). 동의 화면 문구 원본: 온보딩 AI 동의 화면, 설정 › AI 방식 고지.
4. **무료 등급 고지**: Gemini API 무료 등급(Spark)에서는 입력·출력이 Google의 서비스 개선에 쓰이고 사람 검토자가 볼 수 있다 → 그래서 집계 숫자와 범주만 보낸다. 실제 사용자 대상 운영(베타 이후)은 유료 등급으로 옮긴다.
5. 연령: 만 18세 이상만 이용(ADR-0009). Play 타깃 연령 18+.
6. 이용자 권리: 내보내기(설정 › 개인정보 › 내 기록 내보내기, JSON), 삭제(모든 기록 삭제), AI 끄기.
7. AI 생성 콘텐츠 신고: AI가 쓴 문장마다 '신고' — 감사 로그에 표시.

## 6. 기타 체크
- 타깃 연령·콘텐츠 등급: 18+.
- 광고 없음. 인앱 결제 없음.
- 정확한 알람 권한(`SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM`) 선언 없음.
- AI 생성 콘텐츠 정책: 앱 안 신고 동작 있음(05 문서 7절).
