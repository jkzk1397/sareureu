# ADR-0014 친구 연결 보안과 한도

- 상태: 확정 (2026-11-23, 리드 결정)
- 대체: ADR-0012의 5번(QR을 찍으면 바로 연결) → **요청 뒤 수락**. ADR-0012의 4번 중 "서버가 내려 주면 바로 지운다" → **받은 앱이 확인하면 지운다**. 나머지는 그대로다.

## 결정
1. **연결은 두 단계.** 코드를 넣거나 QR을 찍으면 '연결 요청'만 생기고, 코드 주인이 수락해야 친구가 된다. 요청 단계에서 코드 주인에게 보이는 것은 요청한 사람의 닉네임뿐이다. 요청한 사람에게는 수락 전까지 주인의 닉네임·숫자·시청 중 상태를 주지 않는다. 거절은 상대에게 알리지 않는다(요청한 쪽에는 만료될 때까지 '기다리는 중'으로 보인다).
2. **초대 링크로 앱이 열려도 확인 창을 먼저 띄운다.** 링크를 누르게만 해서 친구가 되는 일을 막는다.
3. **초대 코드는 8자리**, 헷갈리는 글자(0·O·1·I·L)를 뺀 31글자에서 고르게 뽑는다. 서버에는 코드가 아니라 SHA-256 해시만 둔다. 주인은 코드를 취소할 수 있다. 코드는 한 번만 쓰인다.
4. **응답으로 정보가 새지 않게** 없는 코드·만료된 코드·차단 관계·주인의 대기 요청이 가득 참은 모두 `404 invite_not_found`다.
5. **한도는 서버가 원자적으로 센다**(한 문장 또는 한 묶음). 두 요청이 동시에 와도 넘지 않는다. 숫자는 서버 `server/src/limits.mjs`, 앱 `core:social`의 `SocialLimits` 한 파일씩에 모은다.
6. **잔소리와 닉네임은 서버도 검사한다**(정규화, 보이지 않는 문자 제거, 금지 표현). 목록 원본은 `docs/05_AI_SPEC.md` 7절 하나이고 앱과 서버가 거기서 만든다. 받는 앱이 한 번 더 검사한다.
7. **신고는 서버에 남긴다.** 서로 다른 3명에게 신고된 계정은 잔소리 보내기가 멈춘다. 운영자가 D1에서 보고 푼다.
8. **잔소리는 받은 앱이 확인(ack)해야 서버에서 지운다.** 확인 전에는 다시 내려 주고 앱이 id로 중복을 거른다.
9. **앱은 `X-App-Version`(친구 서버 계약 번호)을 보낸다.** 서버의 최소 번호보다 낮으면 `426`. 헤더가 없으면 1로 본다(지금 깔려 있는 앱).

## 숫자와 이유
| 항목 | 값 | 이유 |
|---|---|---|
| 코드 길이·글자 | 8자리 · 31글자 | 경우의 수 약 8.5×10¹¹. 6자리(약 8.9×10⁸)는 아래 시도 제한을 더해도 계정을 많이 만들면 맞힐 여지가 있다 |
| 코드 수명 | 24시간, 1회 | 그대로 |
| 연결 요청 수명 | 7일 | 주인이 앱을 매일 열지 않아도 받을 수 있게. 그보다 길면 잊힌 요청이 쌓인다 |
| 한 사람이 받는 대기 요청 | 20개 | 요청 폭탄 방지. 친구 한도(50)보다 작게 |
| 한 사람이 보낸 대기 요청 | 20개 | 코드를 긁어모아 뿌리는 것 방지 |
| 친구 수 | 50명 | 그대로(ADR-0012) |
| 틀린 코드 | 계정마다 10분에 5번, 하루 20번 → `429` + `Retry-After` | 사람이 잘못 치는 횟수는 넉넉히 넘고, 한 계정이 하루 20번이면 맞힐 확률은 사실상 0 |
| 코드 만들기 | 하루 10번 | 새로 만들면 이전 코드가 없어지므로 그 이상은 필요 없다 |
| 차단·끊기 | 합쳐서 하루 50번 | 친구 한도만큼 |
| 잔소리 | 하루 10번(그대로), 같은 친구에게 3번 | 한 사람에게 몰아 보내는 괴롭힘 방지 |
| 신고 | 하루 10번 | 허위 신고로 남을 멈추게 하는 것 방지(멈추려면 서로 다른 3명 필요) |
| 폰 시계 오차 | 서버보다 5분까지 앞서도 받음. 넘으면 `clock_skew` | 자동 시각 맞춤이 꺼진 폰의 흔한 오차. 그 이상은 날짜 경계를 속일 수 있다 |
| 버려진 계정 | 60일 동안 업로드가 없으면 동의 행과 딸린 기록 삭제 | 앱을 지우면 익명 계정을 되찾을 수 없어 서버에 영영 남는다. 앱은 켜져 있으면 하루 한 번은 올린다 |
| 신고 보관 | 180일 | 반복 신고를 볼 수 있게, 무기한은 아니게 |

## IP 기준 제한
- 익명 계정은 얼마든지 만들 수 있어 계정 기준 제한만으로는 부족하다. Cloudflare 무료에서 쓸 수 있는 것은 두 가지를 확인했다(2026-11-23 공식 문서).
  - **Workers Rate Limiting 바인딩**(`[[ratelimits]]`, 정식 출시): 창은 10초 또는 60초뿐이고, 지역마다 따로 세며 대략적이다. 요금제 제한은 문서에 적혀 있지 않다.
  - **WAF rate limiting rule**: 무료는 규칙 1개이고 **zone(자기 도메인)에 거는 것**이라 `*.workers.dev` 주소에는 걸 수 없다. 우리 서버는 `workers.dev`라 쓰지 않는다.
- 그래서 바인딩을 쓴다. 틀린 코드·연결 요청·동의(계정 만들기)·잔소리·신고 경로에 IP마다 60초에 20번. 학교 와이파이처럼 여러 사람이 한 IP를 쓰는 경우를 생각해 넉넉히 잡는다. 바인딩이 없거나 실패하면 통과시킨다(계정 기준 제한은 그대로 동작).
- 바인딩 설정은 서버 코드와 **따로 머지**해서, 무료 계정에서 배포가 실패하면 그 PR만 되돌린다.
- IP는 저장하지 않는다(바인딩 안에서만 센다).

## 감수하는 것
- 코드 해시는 비밀값(pepper) 없이 만든다. 서버 비밀값을 넣으려면 팀원 Cloudflare 계정 로그인이 필요해서다. D1을 통째로 본 사람은 8자리 코드를 맞춰 볼 수 있지만, 코드는 24시간·1회이고 맞혀도 주인의 수락이 필요하다.
- 거절을 숨기느라 요청한 쪽에는 최대 7일 동안 '기다리는 중'이 남는다. 직접 취소할 수 있다.
- 단어 필터는 완벽하지 않다(띄어쓰기·특수문자 우회는 잡지만 새 표현은 못 잡는다). 신고·차단·받는 쪽 재검사를 함께 둔다.
- 60일 넘게 앱을 안 켠 사람은 친구 연결이 사라진다. 동의 화면에 "앱을 지우거나 데이터를 지우면 친구 연결이 사라져"와 함께 알린다.
- 옛 앱(계약 번호 1)은 새 서버에서 코드로 연결할 수 없다(`426`, 앱에는 '연결하지 못했어'로 보임). 친구 목록·시청 중·잔소리 받기는 그대로 동작한다.

## 덧붙임 (2026-11-23): 가짜 앱 막기(App Check)는 지금 넣지 않는다
- **될 수는 있다.** 서버가 App Check 토큰을 직접 확인하는 방법이 공식 문서에 있다(`firebase.google.com/docs/app-check/custom-resource-backend`): 앱이 `X-Firebase-AppCheck` 헤더로 토큰을 보내고, 서버는 `https://firebaseappcheck.googleapis.com/v1/jwks`의 공개 키로 서명·발급자·대상·만료를 확인한다. App Check 자체는 무료이고 Play Integrity 표준 한도는 하루 1만 번이다. Play Integrity 공급자는 Play 밖에서 배포한 앱도 지원한다(서명 인증서 SHA-256 등록).
- **지금 켜면 친구 기능이 모두 막힌다.** 공개 APK는 디버그 빌드라 디버그 공급자를 쓰는데, 디버그 비밀값(`appCheckDebugSecret`)은 공개 APK에 넣지 않기로 했다. 그러면 공개 APK의 토큰은 등록되지 않은 값이라 서버가 거부하게 된다. 릴리스 빌드의 Play Integrity 공급자를 쓰려면 Firebase 콘솔에 앱의 서명 인증서(6-B의 공용 서명 키) SHA-256을 등록하고 Google Cloud에서 Play Integrity API를 켜야 하는데, 이것은 리드가 콘솔에서 해야 하는 일이다.
- **구조 문제도 있다.** App Check 라이브러리는 지금 `core:ai`에만 있고 `core:social`은 `core:ai`에 의존할 수 없다. 토큰 창구를 `core:data`에 두는 계약 변경이 필요하다.
- **그래서 순서를 정해 둔다.** (1) 6-B에서 공용 서명 키로 릴리스 빌드를 만든다. (2) 리드가 콘솔에 SHA-256을 등록하고 Play Integrity API를 켠다. (3) 계약 PR로 토큰 창구를 만들고 앱이 연결 요청·잔소리·신고에 토큰을 보낸다. (4) 서버는 먼저 "확인만 하고 통과"로 며칠 본 뒤, 연결 요청·잔소리·신고 경로부터 거부로 바꾼다(프로젝트 번호는 `wrangler.toml` 변수로). 그 전까지는 계정 기준 한도, 신고, 요청 뒤 수락이 방어선이다.
