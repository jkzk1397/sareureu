# ADR-0015 친구 서버 요청 수 줄이기

- 상태: 확정 (2026-11-23, 리드 결정)
- 대체: ADR-0012의 3번 중 숫자(신호 2초, 서버 판정 5초) → **신호 15초, 서버 판정 40초**. ADR-0012가 "사용자가 늘면 간격을 늘리고 서버 판정 창을 같이 늘린다"고 적어 둔 것을 지금 한다.

## 결정
1. **시청 중 신호는 15초마다**, 서버는 **최근 40초 안**에 신호가 있으면 시청 중으로 본다(신호를 두 번 놓쳐도 이어진다). 멈추면 지금처럼 `false`를 한 번 보내 바로 꺼진다.
2. **친구 탭 새로고침은 15초마다.** 화면을 아래로 당기면 바로 받는다. 화면이 꺼지거나 앱이 뒤로 가면 멈춘다(친구 탭은 화면 수명 주기, 시청 신호는 숏폼 세션이 끝나면).
3. **신호 한 번 = D1 요청 한 번.** 동의 확인, 신호 저장, 확인한 잔소리 지우기, 잔소리 꺼내기를 한 묶음(`batch`)으로 한다. 친구 목록도 동의 확인까지 한 묶음.
4. **서버가 거부하면 조용히 물러난다.** 무료 한도를 다 쓰면 Cloudflare가 요청을 거부한다(Workers는 오류 1027, D1은 질의 실패). 앱은 저장해 둔 친구 목록을 "N분 전 기준"으로 보이고, 주기 요청 간격을 실패할 때마다 두 배로 늘려 5분에서 멈춘다. 몰아서 다시 하지 않고, 성공하면 원래 간격으로 돌아간다.

## 이유 (숫자는 `server/README.md` "무료 한도" 표)
- Cloudflare 무료 한도(2026-11-23 공식 문서): Workers 요청 하루 10만, D1 읽기 하루 500만 행, D1 쓰기 하루 10만 행.
- 2초 신호는 숏폼 1시간에 요청 1,800번·쓰기 1,800번이라, 하루 1시간씩 보는 사용자 약 50명에서 요청과 쓰기 한도가 찼다. 15초로 바꾸면 240번이라 약 350명까지 간다.

## 감수하는 것
- 친구가 숏폼을 켠 뒤 내 화면에 초록 점이 뜨기까지 최대 15초(내 새로고침 주기)가 걸린다. 잔소리는 친구의 다음 신호 때 전달되므로 최대 15초 뒤에 알림이 뜬다(전에는 몇 초).
- 친구가 멈춤 신호 없이 끊기면(앱 강제 종료·네트워크) 최대 40초 동안 시청 중으로 보인다. 그사이에 보낸 잔소리는 서버에 남아 친구가 다음에 볼 때 전달된다.
- 옛 앱(2초 신호)도 새 서버에서 그대로 동작한다(더 자주 보낼 뿐).

## 웹소켓(Durable Objects)으로 바꾸는 방법 — 지금은 하지 않는다
Cloudflare 무료 요금제에서도 Durable Objects를 쓸 수 있다(SQLite 저장소 방식만, 하루 요청 10만·실행 시간 13,000 GB-s, 2026-11-23 공식 문서). 웹소켓 Hibernation API를 쓰면 연결이 쉬는 동안 실행 시간이 세어지지 않고, 들어오는 메시지는 20개를 요청 1번으로 센다. 장점은 초록 점과 잔소리가 바로 전달되고 주기 요청이 사라지는 것이다. 단점은 (1) 숏폼 위에서 도는 포그라운드 서비스가 연결을 계속 들고 있어야 해 배터리와 끊김 처리가 늘고, (2) 친구 관계마다 누구에게 알릴지 정하는 방(객체) 설계와 D1과의 일관성 문제가 새로 생기며, (3) 새 의존성 없이 `HttpURLConnection`만 쓰는 지금 구조로는 웹소켓을 못 쓴다(OkHttp 같은 의존성 추가는 리드 승인 사항)는 점이다. 20:1 계산이 무료 한도에도 그대로 적용되는지는 문서에 분명하지 않다. 사용자가 15초 간격의 한도(약 350명)에 가까워지면 다시 검토한다.

## 결과
- 서버: `limits.watchingWindowMs` 40초, `presence.mjs`·`friends.mjs` 한 묶음 처리.
- 앱: `SocialLimits.PRESENCE_BEAT`·`FRIENDS_POLL` 15초, `PollBackoff`.
