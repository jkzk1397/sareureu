# ADR-0016 녹는 르르: 프레임 6장, 플로팅 버블에서는 '이번 구간 남은 시간'

- 상태: 확정 (2026-11-23, 리드 결정)
- 대체: ADR-0008의 "녹는 단계 그림"(단계별 그림 3장, 없으면 코드로 웅덩이를 그림) → **녹는 프레임 6장**. ADR-0008의 나머지(이름, 각설탕, 얼굴은 코드, 녹아도 아파하지 않는다)는 그대로다.

## 결정
1. **녹는 그림은 프레임 6장**(0·20·40·60·80·100%)이다. `designsystem_buddy_melt_00 ~ _100.webp`. 원본은 `docs/design/reference/ruru_melt_*.png`이고 `docs/brand/tools/cutout.py`로 여섯 장을 같은 크기·같은 좌우 자리·같은 바닥선에 맞춰 만든다. 코드로 웅덩이를 그리거나 몸을 눌러 줄이던 방식은 쓰지 않는다.
2. **`BuddyAvatar`는 0~1의 녹은 정도(`meltFraction`)를 받는다.** 프레임 사이 값은 가장 가까운 장으로 바꾼다. 바뀔 때는 두 장이 짧게 겹쳐 보이고, '애니메이션 제거' 설정이면 바로 바뀐다.
3. **뜻이 자리마다 다르다.**
   - **플로팅 버블**: 녹은 정도 = **이번 구간이 얼마나 지났나**(처음 기준 시간, 또는 '5분만 더'의 5분). 구간이 시작되면 새 각설탕이고, 다음 카드가 올 때쯤 다 녹는다. 연장하면 다시 새 각설탕에서 시작한다.
   - **오늘 탭**: 지금처럼 하루 기준 `MeltStage`(오늘 숏폼 ÷ 내 기준). 같은 프레임 중 하나를 골라 쓴다: `NONE` 0%, `SOFT` 20%, `PUDDLE` 60%, `MELTED` 100%.
4. **녹아도 아파하지 않는다**(ADR-0008 그대로). 표정은 상황으로만 정하고 녹은 정도로 바꾸지 않는다. 우는 얼굴·땀·빨간색·경고 아이콘 금지.
5. 설정의 **'녹는 각설탕 보기'를 끄면 어디서도 녹지 않는다**(부르는 쪽이 0을 넘긴다).
6. **얼굴은 `BuddyFaceGeometry` 하나로** 그리고, 프레임마다 잰 얼굴 자리(`BuddyMelt.anchor`)를 쓴다. 표정 그림 파일을 따로 만들지 않는다.

## 이유
- 버블 위의 진행 링은 "무엇이 차는지"를 설명해야 했다. 각설탕이 녹는 것은 설명 없이 "남은 시간이 줄어든다"로 읽히고, 이름·태그라인과 이어진다.
- 그림 3장은 단계가 바뀔 때 툭 끊겨 보였다. 6장이면 20%씩이라 겹쳐 넘어가는 것만으로 충분히 부드럽다. 사이를 코드로 메우면(몸을 눌러 줄이기) 설탕 결이 뭉개진다.
- 각설탕은 위에서부터 내려앉고 바닥은 그대로라, 앞면 아래쪽에 있는 눈 자리는 여섯 장 모두에서 앞면 안에 남는다. 그래서 눈 자리를 그대로 두었고, 프레임이 바뀌어도 얼굴이 튀지 않는다. 장마다 재서 표(06 문서 8절)로 두고, 가장 작은 크기(28dp)에서도 얼굴이 앞면 위 모서리를 넘지 않는지 시험으로 확인한다.

## 감수하는 것
- 그림 6장으로 앱이 약 290KB 커진다(WebP, 512px).
- 버블과 오늘 탭에서 녹은 정도의 뜻이 다르다(구간 / 하루). 버블은 숏폼 위에서만, 오늘 탭은 앱 안에서만 보이므로 한 화면에 함께 나오지 않는다.

## 결과
- `core:designsystem`: `BuddyAvatar(…, meltFraction: Float? = null)`, `BuddyMelt`(프레임 고르기·얼굴 자리), `BuddyFaceGeometry.shapes(…, anchor)`, `BuddyBitmap.render(…, meltFraction)`, 그림 6장, 르르 그림 판 화면 시험.
- `core:intervention`: 플로팅 버블이 이번 구간 진행을 녹은 정도로 넘기고, 진행 링을 뺀다(다음 PR).
