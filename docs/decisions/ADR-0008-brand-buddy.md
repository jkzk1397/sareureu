# ADR-0008 이름 사르르, 캐릭터 르르(각설탕): 몸은 그림, 얼굴은 코드

- 상태: 확정 (2026-11-05)
- 결정:
  1. 앱 이름 **사르르**, 캐릭터 **르르**(각설탕). 팀 시안 `docs/design/reference/team_mockup.png`를 기준으로 한다.
  2. 르르의 몸은 사진 같은 그림 **한 장**(`designsystem_buddy_body.webp`, 얼굴 없음), 표정 6종은 **코드로 그린 얼굴**(`BuddyFaceGeometry`)이다. 표정별 그림 파일을 만들지 않는다.
  3. 르르는 오늘 숏폼 ÷ 내 기준에 따라 **0~3단계로 녹고**, 새벽 4시에 새 각설탕이 된다. 녹아도 표정은 바뀌지 않으며 아파하거나 울지 않는다.
  4. 코드에는 브랜드 이름을 쓰지 않는다. 접두사 `Pause`, 캐릭터 `Buddy`, 패키지 `com.capstone.pause`. 이름은 `R.string.app_name`·`R.string.buddy_name`에만.
  5. 하루 시계는 시안처럼 **위가 0시**(자정)다. 06 문서 7절.
- 이유:
  - 이미지 생성으로 표정마다 그리면 설탕 결·각도가 매번 달라져 같은 캐릭터로 안 보인다. 얼굴만 코드로 그리면 6표정이 똑같은 몸을 공유하고, 크기마다 얼굴 비율을 조정할 수 있다(작을수록 얼굴을 키움).
  - '녹는다'는 이름·태그라인과 바로 이어지고, 숫자 없이도 "오늘 얼마나 봤나"가 보인다. 다만 캐릭터가 고통받는 모습으로 사용자를 압박하는 방식(키우던 것이 죽는 류)은 죄책감을 만들어 수치심 금지 원칙(PRD 5절 3항 "장난은 OK, 수치심은 NO", AGENTS.md 7절)과 충돌하므로, 녹는 것은 시간 표시로만 쓴다.
  - 이름이 한 번 바뀌었다(콕 → 사르르). 코드가 브랜드에 묶이지 않으면 다음에 또 바뀌어도 비용이 작다.
- 결과: 06 문서 8절이 그리기 계약이다. 새 몸 그림을 넣으면 얼굴 기준점 A를 다시 재고 미리보기로 확인한다. 녹는 단계 그림은 `docs/brand/BRAND_PROMPTS.md`로 만들고, 없을 때는 코드가 웅덩이를 그린다.
