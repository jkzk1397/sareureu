# ADR-0004 감지 소스 세 가지를 같은 인터페이스로

- 상태: 확정 (2026-11-03)
- 결정: `core:sensing`에 `ForegroundSource` 인터페이스를 두고 구현 세 개를 갈아 끼운다.
  1. `UsageStatsSource`(기본): 포그라운드 서비스가 화면이 켜져 있을 때 `UsageStatsManager.queryEvents`를 짧은 주기로 조회해 지금 앞에 있는 앱을 판단. 앱 단위. 권한: 사용 기록 접근.
  2. `AccessibilitySource`(선택 '정밀 모드'): 창 전환 이벤트로 즉시 판단 + 쇼츠·릴스 화면 판별 + 스크롤·클릭 횟수. 판별 규칙은 `assets/surface_rules.json`(원격 설정으로 갱신 가능)에 두고 view ID 하나에 의존하지 않는다.
  3. `DemoEventSource`: 시연용 가상 이벤트, 시계 배속.
- 이유: 접근성은 정확하지만 Play 고지·선언 부담과 앱 업데이트에 따른 깨짐이 있다. 앱 단위는 쇼츠만 못 가르지만 안정적이다. 시연은 권한 없이 돌아야 한다.
- 결과: 세션 생성(`SessionTracker`), 맥락 분류, 경로 계산은 소스와 무관하게 같은 코드. 앱 단위 모드에서는 화면에 "유튜브 전체"라고 정직하게 표시한다.

## 보완 (2026-11-16): 정밀 모드의 고지·동의·거절 흐름
- 상태: 확정 (리드 요청으로 보완, 구현 PR보다 먼저)
- 근거: Play 접근성 API 정책(우리 앱은 장애인 지원 도구가 아니므로 `isAccessibilityTool`을 쓰지 않는다 → 앱 안 고지와 명시적 동의가 필수, 거절해도 앱이 동작해야 함). 조사 원문은 `docs/research/policy.md` 3절.

### 무엇을 보고, 무엇을 남기나
| 구분 | 내용 |
|---|---|
| 보는 것 | 추적 앱(유튜브·인스타그램·틱톡) 창이 바뀔 때, 넘길 때, 누를 때의 화면 구조(뷰 ID·클래스 이름). 다른 앱의 이벤트는 받지 않는다(`packageNames`로 한정). |
| 남기는 것 | "지금 숏폼 화면인가"(참/거짓)로 나눈 시청 구간, 넘김 횟수·넘김 간격의 중앙값, 좋아요·기타 누름 **횟수**. 세션 기록(`ShortformSession.interaction`, `AppSegment.surface`)에만 들어간다. |
| 남기지 않는 것 | 화면 글자, 영상 제목, 채널·계정 이름, 댓글, 메시지 내용, 누른 대상의 글자. 판별할 때 잠깐 읽어도 저장·로그·전송하지 않는다(AGENTS 3절 규칙 5). |
| 하지 않는 것 | 다른 앱을 대신 누르거나 닫거나 넘기지 않는다. `performAction`, `dispatchGesture`, 전역 동작(뒤로·홈)을 쓰지 않는다(규칙 4). 서비스 설정에 `canPerformGestures`·키 이벤트 필터를 켜지 않는다. |
| 밖으로 보내는 것 | 없음. 넘김 횟수도 이 폰 안에서만 쓴다(AI 입력에는 지금처럼 코드가 센 요약만). |

### 고지 화면 문구(앱 안, 다른 고지와 묶지 않는 별도 화면)
- 제목: "정밀 모드를 켤까?"
- 본문:
  1. "접근성 권한으로 유튜브·인스타그램·틱톡 화면이 쇼츠·릴스·피드인지 알아봐. 그래야 유튜브 전체가 아니라 쇼츠를 본 시간만 셀 수 있어."
  2. "남기는 것: 쇼츠 화면이었는지(예/아니오), 넘긴 횟수, 누른 횟수. 이 폰 안에만 남아."
  3. "남기지 않는 것: 화면 글자, 영상 제목, 채널 이름, 댓글, 메시지. 판별할 때 잠깐 봐도 저장하지 않아."
  4. "다른 앱을 대신 누르거나 닫지 않아. 말만 걸어."
  5. "안 켜도 괜찮아. 지금처럼 앱 단위로 계속 셀게."
- 버튼: 주 버튼 "동의하고 켜기"(누르면 동의 기록 → 시스템 접근성 설정 열기), 보조 버튼 "괜찮아, 지금처럼 쓸게".
- 문구 버전: `ConsentItem.ACCESSIBILITY` version 1. 문구가 바뀌면 버전을 올리고 다시 묻는다.

### 흐름
1. 설정 › 감지 › 감지 방식의 '정밀 모드' 스위치를 켠다 → 고지 화면.
2. "괜찮아"(또는 뒤로 가기): 동의 기록을 남기지 않거나 거절로 남기고, 스위치는 꺼진 채 앱 단위로 계속한다. 다시 묻지 않는다(사용자가 스위치를 다시 켤 때만).
3. "동의하고 켜기": `ConsentRepository.record(ACCESSIBILITY, 1, true)` → 시스템 접근성 설정을 연다. 사용자가 거기서 직접 켠다(앱이 대신 켜지 않는다).
4. 돌아왔는데 시스템에서 켜지 않았으면: 스위치 아래 "아직 접근성 설정에서 꺼져 있어. 지금은 앱 단위로 세고 있어"를 보이고 앱 단위로 계속한다.
5. 스위치를 끄면: 동의를 철회로 기록하고, 서비스는 이벤트를 버린 뒤 스스로 꺼진다(`disableSelf`). 감지는 즉시 앱 단위로 돌아간다.
6. 정밀 모드가 실제로 쓰이는 조건 = 동의 기록이 '동의' **그리고** 시스템에서 서비스가 연결됨. 둘 중 하나라도 아니면 앱 단위.
7. 판별 규칙(`assets/surface_rules.json`)이 그 앱에 없거나 읽히지 않으면, 또는 창 구조를 못 읽으면 그 앱은 조용히 앱 단위로 센다(사용자에게 오류를 띄우지 않는다).
8. 시연 모드는 권한 없이 지금처럼 `DemoEventSource`로 돈다.

### Play 제출
- 접근성 API 선언서: 필요한 이유("사용 기록 접근으로는 유튜브 앱 안에서 쇼츠인지 일반 화면인지 구분할 수 없음"), 수집 항목(위 '남기는 것'), 공유 없음.
- 동영상: 위 1~5 흐름, **거절하는 경우 포함**.
