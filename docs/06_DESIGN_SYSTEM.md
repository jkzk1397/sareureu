# 06. 디자인 시스템 — "Paper & Ink + Lime"

> 담당: R5 · 토큰은 `core:designsystem`의 `PauseColors`, `PauseType`, `PauseShape`, `PauseSpacing`이 유일한 원본이다. 화면에서 hex·dp를 직접 쓰지 않는다.
> 목업: `docs/design/mockups/*.png` (라이트·다크). 목업과 이 문서가 다르면 **이 문서가 우선**이다.

## 1. 방향
- 키워드: **장난스러운 · 선명한 · 친근한 · 밤에도 편한**.
- UI 대부분은 종이(paper)와 잉크(ink)의 무채색. 색은 **라임 형광펜 하나**와 **차트의 맥락 색**만 쓴다. 색이 적어야 캐릭터와 데이터가 산다.
- 라이트 모드의 주 버튼은 **잉크 바탕 + 라임 글자**, 다크 모드는 **라임 바탕 + 잉크 글자**(반전).
- 밤 사용이 많으므로 다크 모드를 먼저 확인한다. 순검정(#000) 대신 아주 어두운 잉크.

검증 결과(인접 쌍, 라이트 `#FFFFFF`·다크 `#1A1A1F` 위):
- 라이트: 명도·채도 통과, 색약 ΔE 최저 9.2(목표 8 이상), 정상 시각 ΔE 최저 24.0. 이동·식사·자기 전은 바탕 대비 3:1 미만 → **직접 라벨 또는 표 보기 필수**.
- 다크: 대비 모두 3:1 이상, 정상 시각 ΔE 최저 19.7. 식사↔쉬는 시간 색약 ΔE 6.9(경고 구간) → **2px 바탕 간격 + 아이콘 + 라벨을 반드시 함께** 쓴다.
- 산점도처럼 모든 쌍이 맞닿는 차트에는 맥락 색을 3개까지만. 넘으면 "기타"로 접거나 작은 차트로 나눈다.
- 맥락은 **아이콘과 이름을 항상 같이** 쓴다. 색만으로 맥락을 알리지 않는다.

### 2.3 크기·연속값 색
- 히트맵(요일×시간): 한 가지 색의 단계(파랑 `#CDE2FB` → `#104281`, 다크는 어두운 쪽을 0으로 뒤집는다). 0분 칸은 `surfaceAlt`.

## 4. 모양·간격·움직임
- 모서리: 카드 28dp, 시트 32dp(위만), 칩·버튼 완전 둥글게(pill), 작은 요소 12dp.

- 그림자 대신 `line` 1dp 테두리 또는 `surface`/`bg` 명도 차. 오버레이 카드만 그림자(elevation 8dp).
- 움직임: 기본 220ms `FastOutSlowIn`. 캐릭터 대기 동작은 2.4초 주기 위아래 1dp(8절). **시스템 '애니메이션 제거'가 켜져 있으면 모두 끈다.**

## 5. 캐릭터 르르 (Buddy) — 요약
- **각설탕** 한 개. 오늘 숏폼을 본 만큼 조금씩 녹고(웅덩이), 새벽 4시에 새 각설탕으로 돌아온다. 이름 '사르르'(사르르 녹다)와 짝을 이룬다.
- 몸은 그림 한 장, 얼굴(눈·눈썹·입)은 코드로 그린다. 표정 6종: 기본 `NEUTRAL` · 보는 중 `WATCHING` · 말 걸기 `CALLING` · 걱정 `WORRIED` · 칭찬 `CHEER` · 졸림 `SLEEPY`. 자세한 좌표·크기·녹는 단계는 **8절**.
- 말투: 반말·짧게·이모지 최대 1개. 놀리되 비하하지 않는다. 사용자가 고른 말투(친구처럼/다정하게/담백하게)를 따른다. 조사는 받침 없는 이름에 맞춰 '르르가·르르는·르르에게·르르랑'.

## 7. 하루 시계 `DayClock` 명세
- **방향**: 한 바퀴가 24시간. **위가 0시(자정)**, 오른쪽 6시, 아래 12시(낮), 왼쪽 18시. 시계 방향으로 시간이 흐른다. 팀 시안과 같고, 수면 앱의 24시간 다이얼과 같은 관례다. 이 앱이 가장 보여 주고 싶은 '자기 전·한밤중'이 위쪽, 가장 눈에 띄는 자리에 온다.
- **다이얼**: 원 전체는 `bg` 톤, **위 반(18시→0시→6시)은 밤**이라 한 단계 어둡게(라이트 `#E4E4DC`, 다크 `#141418`). 1시간마다 점 눈금, 0·6·12·18시는 큰 점 + 바깥 라벨("0시", "6", "12시", "18").
- **꽃잎**: 1시간 칸마다 꽃잎 하나. 안쪽 반지름에서 시작해 **길이 = 그 시간에 본 분**(오늘: 30분 = 55dp, 일주일: 최댓값 = 54dp로 정규화). 한 시간 안에 여러 맥락이 있으면 맥락 순서(기상→한밤중)대로 바깥으로 쌓는다. 꽃잎 사이 간격은 6분 각도(≈1.5°).
- **가운데**: `surface` 원 + 합계("1시간 12분") + 작은 라벨("오늘 숏폼"/"일주일").
- **지금**: 현재 시각 위치의 테두리에 라임 점(잉크 테두리). 보는 중이면 그 시간 꽃잎이 실시간으로 자란다.
- **위험 시간대**: 다이얼 테두리에 잉크 점선 호(`RiskWindow` 상위 구간).
- **상호작용**: 꽃잎 탭 → 그 시간의 세션 목록 시트. 길게 누르면 툴팁(시간·분·맥락). "표" 토글이나 TalkBack에서는 같은 데이터를 표로 읽는다.
- **구현**: Compose `Canvas` + `drawArc`(꽃잎은 `Path`의 annular sector). 각도 = `분 / 1440 × 360°`, 시작각은 위(0시, Compose `drawArc` 기준 -90°). 계산은 `core:insights.ClockBins`(시간별·맥락별 분) 순수 함수가 만든다.
- 왜 원형인가: "밤에 몰려 있다"가 한눈에 보이는 게 이 앱의 핵심 메시지다. 정확한 비교는 아래의 맥락별 막대와 표 보기가 맡는다.
- 팀 시안과의 차이(시안 `docs/design/reference/team_mockup.png`는 느낌의 기준이고, 아래는 일부러 다르게 정한 것): ① 시안의 꼭대기 라벨 '24시'는 '0시'로 쓴다. ② 탭은 시안의 4개(오늘·리포트·대화·친구)가 아니라 **5개(오늘·리포트·코치·친구·설정)**. ③ 채팅 입력의 마이크(음성 입력)는 P1. ④ 시안은 고리(구간 호)지만 우리는 **꽃잎(시간당 본 분)** 을 쓴다. 길이로 '얼마나'까지 보이기 때문이다. 시계 색은 **언제(맥락)** 만 뜻한다. 시안의 '메신저에서 넘어옴'은 경로라서 시계가 아니라 `FlowDiagram`에 둔다.

## 8. 르르 그리기 명세 (`BuddyAvatar`)
**구성**: 몸 = 그림 한 장 `core/designsystem/src/main/res/drawable-nodpi/designsystem_buddy_body.webp`(512×512, 투명 배경, 각설탕 + 오른쪽 아래 작은 웅덩이, **얼굴 없음**). 얼굴 = 코드로 그린 눈·눈썹·입(+반짝이·z). 표정마다 그림을 새로 만들지 않는다(이미지 생성으로 다시 그리면 설탕 결이 매번 달라진다).

**API**
```kotlin
enum class BuddyExpression { NEUTRAL, WATCHING, CALLING, WORRIED, CHEER, SLEEPY }
enum class MeltStage { NONE, SOFT, PUDDLE, MELTED }   // 0~3
@Composable fun BuddyAvatar(expression: BuddyExpression, size: Dp, modifier: Modifier = Modifier,
                            melt: MeltStage = MeltStage.NONE, shadow: Boolean = !isSystemInDarkTheme())
object BuddyFaceGeometry { fun shapes(expression: BuddyExpression, sizePx: Float, density: Float): List<FaceShape> }  // 순수 Kotlin
object BuddyBitmap { fun render(context: Context, expression: BuddyExpression, sizePx: Int): Bitmap }           // 알림 아이콘용
```
`BuddyExpression`·`MeltStage`는 `core:model`(계약), 나머지는 `core:designsystem`. `BuddyAvatar`(Compose `DrawScope`)와 `BuddyBitmap`(`android.graphics.Canvas`)은 같은 `BuddyFaceGeometry`를 그린다. 기하 계산은 한 곳에만. `contentDescription` = "르르, {표정 이름}".

**좌표계**: 몸 그림 정사각형을 0~100으로 본다. 얼굴 기준점(두 눈 사이 가운데) **A = (39.7, 78.0)**, 기본 눈 간격 **g₀ = 11.3**. 모든 점은 `A + (x·g, y·g)`.
- **작을수록 얼굴을 키운다**: `g = min(max(g₀, 14dp를 0~100 단위로 바꾼 값), 32)` (예: 56dp면 14dp = 25 단위라 g = 25). 눈 반높이 `ry = max(0.095g, 2dp)`, 눈 반너비 `rx = 0.62·ry`, 선 굵기 `max(0.06g, 1.6dp)`, 끝은 둥글게. (2026-11 리드 요청으로 작은 크기 최솟값을 10dp·1.3dp·1.1dp에서 올림 — 28~56dp에서 눈코입이 점처럼 작아 안 보였다.) 색은 라이트·다크 모두 `#141416`(각설탕이 흰색이라).
- 곡선은 2차 베지어 `시작 → 조절점 → 끝`.

| 표정 | 눈 | 눈썹 | 입 | 덧붙임 | 쓰는 곳 |
|---|---|---|---|---|---|
| `NEUTRAL` 기본 | 타원 (±0.5, 0) | — | (−0.13, 0.17) → (0, 0.29) → (0.13, 0.17) | — | 오늘 인사, 채팅, 앱 아이콘, 고지 |

참고 구현(웹 목업에 쓴 것과 같은 값): `docs/brand/ruru_face_reference.py`. 작은 크기의 최솟값(말 걸기 입 타원 1.5·1.7dp, 졸림 입 원 1.3dp, 보는 중 눈 폭 ×1.05 등)은 표가 아니라 이 참고 구현을 따른다. 녹을 때 몸은 바닥 기준으로 세로로 눌리지만 얼굴은 모양을 그대로 두고 위치만 몸을 따라 내려간다(`BuddyFaceGeometry.squashed`).

**녹는 단계 `MeltStage`** — 오늘 숏폼 ÷ 내 기준(`Baseline`의 하루 평균, 기준선이 생기기 전 첫 7일은 `Profile.dailyGoalMinutes`, 기본 60분):
| 단계 | 조건 | 그림 |
|---|---|---|
| `NONE` 0 | 50% 미만 | 몸 그대로 |
| `SOFT` 1 | 50~100% | 웅덩이 폭 62% |
| `PUDDLE` 2 | 100~150% | 웅덩이 82%, 몸 높이 ×0.88 |
| `MELTED` 3 | 150% 이상(최대) | 웅덩이 100%, 몸 높이 ×0.78 |
- 계산은 `core:insights`의 순수 함수 `MeltStageCalculator(todayMinutes, baselineMinutes)`. 새벽 4시(`DayBoundary`)에 0으로.
- 그리기: `designsystem_buddy_melt_1~3.webp`가 있으면 그 그림을 쓰고(만드는 법은 `docs/brand/BRAND_PROMPTS.md`), 없으면 코드로 그린다 — 몸 아래 타원 웅덩이(높이 13%, `#ECF0E8` 95%, 아래쪽 안쪽 그림자) + 몸을 바닥 기준으로 세로 축소. 단계가 바뀔 때 600ms, '애니메이션 제거'면 즉시.
- **녹아도 아파하지 않는다.** 표정은 상황(맥락·단계)으로만 정하고 녹은 정도로 바꾸지 않는다. 우는 얼굴·땀·빨간색·경고 아이콘 금지. 녹는 건 시간 표시일 뿐 벌이 아니다. 오늘 화면과 플로팅 버블에서만 보이고, 설정에서 끌 수 있다(`showMelt`).
